# OnMyLead Feature-Parity Tracker

The one place that says where every feature stands on every device. Every pull request that adds,
changes or removes a feature updates its row here (`CLAUDE.md` Rule 8). Never mark a cell ✅ that
wasn't checked; "the code is shared" is 🟡 until it runs on that device.

Last full audit: 2026-10-14 against `main` 4559b8f (`docs/feature-inventory.md`).

## Legend

| Mark | Meaning |
|---|---|
| ✅ | Built and verified on that device / layer |
| 🟡 | Shared code that should work there, but not built or tested on that device yet |
| 🔨 | In progress (link the pull request in Notes) |
| ⬜ | Missing: needs work before that device can ship it |
| ➖ | Not applicable (see Exceptions) |

Columns: **iPhone**, **iPad**, **Android Phone**, **Android Tablet** = the app on that device
(iPad and Android tablet also mean a tablet layout, not a stretched phone screen). **Backend** =
database, RPCs and edge functions support it for every store and device. **Admin** = the Admin
Dashboard shows or manages it where relevant. **Docs** = Help Center article(s) cover it.
**Release** = the store version that carries it.

Today's device-wide state (2026-10-15): OnMyLead 1.0 build 3 (from `22c7a3f`) is submitted to the
App Store for iPhone and iPad, and the same code is submitted to Google Play for Android phones and
tablets. The Help Center and onmylead.com treat iPad and Android as released. Cells stay 🟡 until a
feature is checked on that device: iPhone is device-tested, tablets and Android mostly only on the
web build and the Android emulator.

## Exceptions

| ID | Feature | Devices | Why |
|---|---|---|---|
| E01 | CarPlay | iPhone only | CarPlay runs on iPhone only (Apple granted the Driving Task entitlement 2026-11-04). Android Auto is not planned (a separate Google review and car app library); iPad and Android tablets have no car mode, and the website can't reach a car. |
| E02 | Admin Dashboard | Website only | Owner tool at onmylead.com/admin; phone apps link to it from the first row of the You tab (admins only, 2.1). |
| E03 | Offline maps | Apps only | The website can't store map tiles. |
| E04 | Sign in with Apple on Android and the website | Browser flow | Apple ships its sheet only on iPhone and iPad; Android and onmylead.com open Apple's web sign-in in a browser sheet instead (same account), once the owner's apple_web_sign_in flag is on. |
| E05 | Purchases | Per store | Apple devices buy through the App Store, Android through Google Play, the website sells nothing; one Pro state on the server for all. |
| E06 | Recording a trail in Navigate | Apps only | Recording needs continuous GPS with the screen on, which a browser tab can't keep. The website has Explore, Measure, My Trails (kept in that browser), sharing and ratings. |
| E07 | Music Controls: play, pause and skip for other apps | Android only (iPhone/iPad: Apple Music only); none on the website | Apple has no API for apps to control another app's playback; Spotify's iOS remote SDK is limited to apps Spotify approves, so on iPhone and iPad Spotify and other apps get volume (MPVolumeView) and Open Spotify. Browsers can't reach the phone's music. |
| E08 | Event links (/e/*) opening in the iPhone and iPad app | iPhone/iPad from the website deploy after 2.0 is live | Apple's association file applies to every installed build, and 1.0.3 has no event screen, so `/e/*` joins `public/.well-known/apple-app-site-association` and `APP_LINK_PATHS` only once 2.0 is the App Store version. Until then event links open on onmylead.com (which works fully). Android declares the path in the 2.0 build itself. |
| E09 | Tilt meter and Crash Alert | Apps only | They read the phone or tablet's motion sensors; a computer has none. The website's /tilt says so; the showcase still describes the feature. |
| E10 | Tablets and the website on Free | Pro on big screens | Chris made iPad, Android tablets and the website Pro (2026-11-03). A Free account there gets a cover with Join a Ride, Your Rides, See OnMyLead Pro and the account; joining, the ride page and Ride Mode stay open so following the leader is free on every device. |
| E11 | App language: right-to-left languages (Arabic, Hebrew, Urdu, Persian) and the signed-out onmylead.com homepage | All devices | Right-to-left needs every screen's layout mirrored (I18nManager plus a restart), a separate project; the 12 languages shipped all read left to right. The marketing homepage is long-form English copy and stays English; the signed-in website follows the rider's language. |
| E12 | Bluetooth Sharing | Apps only | A website can't use Bluetooth to reach other phones in the background. Riders following on the website see relayed spots once any rider's phone uploads them. |
| E13 | App language: lock-screen push notifications, emails, the Admin Dashboard, Terms of Use and Privacy Policy | All devices | Push and email text is written on the server, which doesn't know each rider's language yet (would need the language synced to the profile and per-language templates). The admin dashboard is Chris-only. The legal pages stay in English so there is one binding text. Everything riders see inside the app is translated. |
| E14 | Map Features on the flat fallback maps (Apple, Google, website Leaflet) | All devices, only when Mapbox can't draw | Highways and paved public roads are drawn from OpenStreetMap by Mapbox. When a map falls back to the 2.0 flat map (no token, Mapbox Maps flag off, no signal outside a saved 3D pack), the base map shows roads in its own colors instead; trails, hiking paths, closures and land still follow the switches. Land squares aren't saved in offline downloads yet. |
| E15 | Zoom In at Intersections and the compass arrow on your own dot | Mapbox maps only (intersections); apps only (compass) | Junctions are found in the road and trail lines Mapbox has drawn, which the fallback Apple, Google and Leaflet maps don't expose, so with Mapbox off the map keeps its zoom at junctions. Browsers have no dependable compass, so on onmylead.com your dot keeps its last GPS direction when you stop. |
| E16 | Leader Trackline on the website's route sketch | Website, only when Mapbox can't draw | Without Mapbox the website's Ride Mode shows a drawing of the route (or a list of riders), not a live map, so there is no map to draw the leader's line on. The live Mapbox map on onmylead.com draws it like the apps. |
| E17 | Emergency Siren with the app closed | iPhone and iPad follow the ring/silent switch | A push sound on iPhone and iPad is muted by the silent switch unless it is a Critical Alert, which needs an entitlement Apple grants on request (not requested yet; Chris's call). Android plays the siren channel as an alarm. With OnMyLead open, every device plays it even on silent. |
| E18 | Google Ads conversions inside the app | iPhone, iPad, Android | Google measures in-app conversions through the Firebase Analytics SDK, which would add a large native SDK (and static frameworks on iOS) to the build. The app sends Meta and TikTok events from the server instead; Google gets website conversions from the Google tag, and Android installs from Google App campaigns are counted by Google Play once Google Ads is linked to the Play Console. Adding Firebase Analytics is a follow-up issue if Chris runs Google app-install campaigns. |
